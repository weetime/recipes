MiniMax-H3 视频生成基准测试

日期 2026-08-31 ~ 09-01 硬件 8 × RTX PRO 6000 Blackwell 96GB 引擎 vllm-omni 0.1.dev2381 · SGLang ga1fe4e30a 精度 BF16

2026-09-01 结案：根因已修复，全矩阵重测完成

初测性能低于预期，排查发现 PCIe ACS 重定向影响 GPU 对等通信。修复后 NCCL all_reduce 带宽从 8.4 提升至 22.8 GB/s，四卡 T2VA 耗时从 329.0 降至 191.1 秒（1.72×）。本文仅报告修复后的性能结果，不公开主机修改步骤；涉及 PCIe 设备隔离的配置应由基础设施维护者评估。

本报告不是 MLPerf 提交，不报 MLPerf 分数

MLPerf Inference v6.0 的文生视频基准钉死的模型是 Wan2.2-T2V-A14B，本次被测对象是 MiniMax-H3，两者不可互换。本报告的做法是照搬 MLPerf 的测试规程（标准数据集、确定性控制、场景定义、报数纪律），使结果可复现、可被第三方参考，而非声称任何 MLPerf 成绩。

两份配置除 TP/USP 拆分外完全相同（text-encoder-tp=4、vae-patch-parallel=4、CPU、镜像、环境变量、卡组一字未动），是单变量对照。极差 0.12% / 0.13%，产物逐字节一致。

ACS 对两种拆分的惩罚不对等。TP4 的并发集合通信比 TP2×USP2 密集，被 ACS 罚得更狠——所以修复后 C 的提速（2.39× / 2.74×）显著大于 B（1.73× / 1.92×）。修复前两者看着差 1.5~1.6 倍，修复后只差 10~14%。在被污染的环境下做配置对比，方向可能对，量级会离谱。

修正后的结论：TP2×USP2 仍是 4 卡最优，但优势有限，不构成数量级差距。「PCIe 机器上 TP 度数取显存下限、其余给序列并行」这一方向性建议依然成立，但 TP4 不应再被描述为「负收益」。

结论依据
SGLang 全程领先，幅度随卡数上升~7% → ~8% → ~11%，两种任务同步。测试节点 8 卡必须横跨两个 PCIe 组走 SYS，通信压力最大的那档差距也最大——指向两者序列并行实现对拓扑劣势的耐受度不同。
参考条件化的代价与引擎无关Ref/FL 比值：2 卡 1.67× / 1.66×、4 卡 1.61× / 1.61×、8 卡 1.56× / 1.58×。两个独立实现三个卡数全部重合 ⇒ 这是模型架构决定的（参考 token 拼进 DiT 注意力序列，每个去噪步重付），非某引擎实现问题。机制另有上游文字佐证。
扩展比 SGLang 略优FL2VA 1.68× / 1.46× vs 1.66× / 1.41×；Ref2VA 1.73× / 1.49× vs 1.72× / 1.45×。
SGLang 显存全面更省FL2VA 71.1 / 58.5 / 51.8 GB，Ref2VA 74.0 / 59.5 / 52.9 GB；vllm-omni 4 卡为 80.8 GB。
口径差异vllm-omniSGLang

这些差异是各自官方配方的一部分，不是可对齐的参数。三点必须随数字一起读：① 预热时机的差异对 SGLang 的单条延迟有利，公平起见须同报启动耗时——SGLang 从 pod 创建到 Uvicorn running 约 5~7 分钟。② 码率差约 7.5 倍，两边产物不可按字节或视觉质量直接比较；inference_time_s 由服务端计时、不含封装，故速度结论不受影响，但 SGLang 的编码参数尚未查明。③ 主指标口径不同（服务端 vs 客户端），SGLang 客户端墙钟比 inference_time_s 多 1.8~3.4 s；若统一按客户端口径，SGLang 领先幅度会略微收窄，方向不变。

未覆盖：吞吐与容量（全程并发 1，无 QPS、无拐点、无扩容依据）、长跑稳定性、输出质量比对（未做 SSIM/PSNR/VBench，不能声称两个引擎输出等价）。

已知工具缺陷

后续测试须规避
  1. image_pixels 统计字段把高度写死为 768。实际公式为 (宽/16) × 48 × 帧数，7 个已知点全部精确命中。据它反推分辨率会得到错误结论。
  2. stage_gen_time_ms 包含排队时间。实测一条计算仅 199 秒的请求因排队被记为 580 秒。仅当 queue_wait ≈ 0 时它等于计算耗时。
  3. denoise_step_latency_ms 不是单步耗时。它等于 stage_gen_time_ms ÷ 步数，既摊入固定开销也含排队。
  4. 压测客户端轮询超时写死 600 秒（backends.py）。超时请求被记为失败而非「慢但成功」，P1 档必然触发。本次使用仅修改该行的副本。
  5. 工具自带 warmup 对 t2v 强制 num_frames=1（_make_warmup_request），形状与实测不符。本次改用外部同形状预热并置 --warmup-requests 0。
  6. VBench-I2V 标准图集当前不可获取：官方 download_data.sh 使用 gdown --id，该参数在 gdown 6.x 已移除，脚本本身失效；三个文件均托管于 Google Drive。因此本轮合规基准只覆盖 t2va。
测试方法与负载定义为本系列共用，后续配置沿用同一规程，结果回填测试矩阵。
FL2VA（图生视频）合规数据待标准图集来源解决后补充；已测得同画布下 fl2va ≈ t2va × 1.06 可作换算参考。
Ref2VA 一节使用固定单图 + 5 秒音频参考（本构建拒绝纯图请求，与官方文档不符），并发恒为 1，不含吞吐与容量结论。
