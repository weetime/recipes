# P2a — Vendor SGLang Upstream + Transformer (TP, overlap models) — Design

- 日期: 2026-06-03
- 状态: 已批准设计,待实现计划
- 父设计: `docs/superpowers/specs/2026-06-03-unify-vllm-sglang-recipes-design.md`(Approach B)、`docs/superpowers/specs/2026-06-03-engine-switcher-slice-design.md`(切片)
- 目标: 用真实上游数据 + transformer **自动生成** `engines/sglang/` 块,替换切片里手写的两个块,让所有与 vLLM recipe 重叠的模型一次性长出引擎切换器。P2a 故意只做 TP,defer dp/ep/PD/speculative/SGLang-only/多节点忠实 tp。

## 背景:上游真实形状(已侦察)

`sgl-project/sgl-cookbook`(正在并入主 `sglang` 仓):
- 可消费源:`data/models/generated/<version>/*.yaml`(schema 规整;源 `src/` 是简化格式,不用)。
- `data/models/vendors.yaml`:`vendor id → huggingface_org`(路径大小写来源,如 `qwen → Qwen`)。
- 每个 model 给:`model_path`(= HF id)、`attributes.llm.{tool_parser, reasoning_parser, thinking_capability, chat_template}`、`hardware: {H100,H200,B200: {configurations:[…]}}`,每个 config 有 `attributes:{nodes:single|multi, quantization}`、`quantized_model_path`,以及 `engine:{env_vars, tp, dp, ep, enable_dp_attention, extra_args}` **或** `prefill`+`decode`(PD)。
- **目录按版本分散**:最新 `v0.5.10` 仅 5 个模型,旧版本(v0.5.6/v0.5.8)更多 → 必须跨版本合并。

## 已确认决策(brainstorming)

1. **Vendoring = fetch 脚本 + lock 文件**(非 subtree、非构建时现拉)。
2. **TP = 遵上游 per-hw tp**,映射到 taxonomy 硬件 id,上游未给的硬件回落 `gpu_count`。
3. 范围 = TP only、overlap-only;dp/ep/PD/speculative/SGLang-only/忠实多节点 tp 全 defer。

## 组件设计

### 1. Vendoring —— `scripts/fetch-sglang-upstream.mjs` + `upstream/sglang.lock`

- 脚本用 GitHub API(tarball 或 contents API)拉取 `sgl-project/sgl-cookbook` 的:
  - `data/models/generated/v*/*.yaml`
  - `data/models/vendors.yaml`
  到 `upstream/sglang/`(保持相对目录结构)。
- `upstream/sglang.lock`(JSON):`{ repo: "sgl-project/sgl-cookbook", ref: "<commit SHA>", fetched_at: "<注入>", paths: [...] }`。ref 锁定 commit,保证可重现。
- `upstream/sglang/` **进 git**(diff 可审);头部不需特殊标记(它是 vendored 原样)。
- 上游迁到主 sglang 仓时:只改 lock 的 `repo` + 脚本里的相对路径前缀,不动其它。
- 时间戳由调用方注入(脚本内不可用 `Date.now()` 之类——但这是普通 node 脚本,可用 `new Date()`;若放进 workflow 才有限制。此处普通脚本,直接用系统时间)。

### 2. Transformer —— `scripts/sync-sglang.mjs`

读 `upstream/sglang/` 的 vendored 文件,产出 `engines/sglang/<org>/<repo>.yaml`。纯函数逻辑抽到 `src/lib/engines/sglang-transform.js`(可单测),脚本只做 IO(读 vendored、写块、打印摘要)。

流程:
1. 读 `vendors.yaml` → `vendor → huggingface_org` map。
2. 遍历所有 `generated/v*/*.yaml`,展开 `families[].models[]`;按 `model_path` 聚合,**latest-wins**(版本号比较,取最高;`min_version` = 该版本)。
3. **overlap 过滤**:`model_path` 对应 `models/<org>/<repo>.yaml` 存在才生成块;否则跳过并计数。`log` 输出 `生成 N 块,跳过 M 个 SGLang-only 模型`。
4. 字段映射(每模型):

| 上游字段 | → 块字段 |
|---|---|
| `model_path` | 文件路径 `engines/sglang/<model_path>.yaml` + `model_id` |
| (固定) | `serve_binary: "python3 -m sglang.launch_server"` |
| (固定) | `base_args: ["--trust-remote-code"]`(再并入 default config 的 `engine.extra_args`,去重) |
| `attributes.llm.tool_parser`(非 null) | `features.tool_calling.args: ["--tool-call-parser", <v>]` |
| `attributes.llm.reasoning_parser`(非 null) | `features.reasoning.args: ["--reasoning-parser", <v>]` |
| `hardware.<HW>.configurations[name=="default"].engine.tp` | `tp_by_hardware.<taxonomy-id>`(经 HW 名映射) |
| config(`name=="default"`)`attributes.quantization` + `quantized_model_path` | `variants.<precision>`(precision=quantization;有 `quantized_model_path` 时加 `model_id` override) |
| 任一 config `attributes.nodes == "multi"` | 追加 `strategies.multi_node_tp`(带切片同款 `extra` 模板) |
| (恒有) | `strategies.single_node_tp: {}` |

5. **硬件名映射表**(`src/lib/engines/sglang-transform.js` 内常量):`{ H100:"h100", H200:"h200", B200:"b200", B300:"b300", GB200:"gb200", GB300:"gb300", MI300X:"mi300x", MI325X:"mi325x", MI355X:"mi355x" }`(以 taxonomy.yaml 实际 id 为准,实现时核对;映射不到的 HW 名 → `log` 警告并跳过该 hw 的 tp)。
6. 块头部写 `# GENERATED by scripts/sync-sglang.mjs — do not edit`。

**只取 `default` 命名配置**:`speculative-mtp` 等其它命名配置(含 dp/ep/PD)P2a 一律忽略(留后续)。

### 3. 块 schema 变更 + adapter 扩展

块新增可选字段 `tp_by_hardware: { <taxonomy-hw-id>: <int> }`。

`src/lib/engines/sglang/index.js` 改两处:
- TP 解析:`const tp = block.tp_by_hardware?.[hwId] ?? gpuCount`(单节点);多节点 `tp = (block.tp_by_hardware?.[hwId] ?? gpuCount) * nodeCount`(忠实多节点 tp 留后续——这里仍是通用 ×nodes)。
- 返回值新增 `tp` 字段(单节点与多节点都带),供 UI summary 读。

`CommandBuilder.jsx` config summary:把 P2a 之前 `summaryTp = gpu_count×…` 改为**优先读 `result.tp`**(非 vLLM 引擎),保证摘要与命令 tp 一致。(若 #3 已合并则在其基础上改;P2a 分支需 rebase 到含 #3 的 main。)

切片 adapter 测试里 `tp = gpu_count` 的断言:DeepSeek-V3 的生成块 `tp_by_hardware` 若上游标注非 8,断言值会变——实现时以生成块实际值更新测试,不是回归。

### 4. 落地效果

- `engines/sglang/` 由手写变**生成树**;切片那两个手写块被 transformer 重新产出(内容可能因 per-hw tp 而更精确)。
- 所有 overlap 模型长出切换器。

## 明确不做(后续 PR)

- dp / ep / `enable_dp_attention`、PD(prefill+decode)、speculative-mtp 等非 default 配置。
- 忠实多节点 tp(P2a 多节点仍 gpu_count×nodes)。
- SGLang-only 模型进站(P2c,需合成最小 meta)。
- sync CI / drift PR(P5)。

## 验证

- `node --test` 全绿;新增:
  - `sglang-transform` 单测:喂 fixture 上游 generated YAML + vendors,断言 (a) parser→feature 映射、(b) per-hw tp 经映射表落到 taxonomy id、(c) quantization→variant(+model_id override)、(d) overlap 命中/跳过、(e) 跨版本 latest-wins。
  - adapter 单测:`tp_by_hardware` 命中查表、缺失回落 gpu_count、返回带 `tp`。
- `node scripts/build-recipes-api.mjs && node scripts/snapshot-api.mjs`:重生成 golden;**人工确认 diff 仅涉及 overlap 模型的 JSON**(其余模型字节不变)。
- 构建摘要打印生成/跳过计数。
- 实测:overlap 里挑一个单卡可跑的小模型,页面切 SGLang 看 tp 与命令正确。

## 开放问题 / 后续

- 硬件名映射表以 `taxonomy.yaml` 实际 id 为准,实现时核对(尤其 AMD / GB NVL4 命名)。
- 上游 `generated/` 的版本号排序:形如 `v0.5.10` > `v0.5.8` > `v0.5.6`,需按 semver 数值比较(`v0.5.10` 不能被字符串比较判成小于 `v0.5.8`)。
- transformer 与 `attachEngines` 的关系不变:transformer 只产出 `engines/sglang/` 文件,join(`sglang-join.js`)逻辑沿用切片不动。
- **实现期发现**:当前上游 `generated/` 里所有 config 都标 `nodes: single`(无一个 `multi`),所以 transformer/adapter 的多节点分支目前是 dead code(仅单测覆盖)。后果:像 GLM-5.1 这种 H100 tp=32 的会渲染成单节点 `--tp 32`(实为 4 节点),忠实镜像了上游(尚不完整)的标注。忠实多节点 tp 留 P2 后续(可由 `tp / gpus_per_node` 推 node 数,或等上游补 `nodes: multi`)。
